# Исследование и текущее состояние проекта yt-dll

## 1. Текущее состояние (на момент завершения разработки ядра)
- **Функционал:** Реализован сканер каналов (только опубликованные видео), защита от дублей по `videoId`, поддержка плейлистов, механизм паузы/продолжения загрузки, автоматическая очистка просмотренного.
- **Хранилище:** Файлы в формате `.mp4` (H.264 + AAC). Текущий объем ~19 ГБ.
- **Плейлисты:** Логические плейлисты (`Playlist_1`, `Подписки`) хранятся только в `state.json`. На диске файлы `.m3u` отсутствуют.
- **API/UI:** Веб-интерфейс (Glassmorphism) позволяет управлять очередью, каналами и смотреть видео через браузер (HTTP Range).

## 2. Анализ целевого оборудования (Raspberry Pi 5 + Android TV)
### Кодеки и воспроизведение
- Текущий формат (`MP4`, `H.264`, `AAC`) является универсальным ("Direct Play") для всех современных устройств: Android TV, Smart TV, смартфоны. Это означает **минимальную нагрузку на CPU** (не нужен транскодинг).

### Сравнение медиасерверов
| Характеристика | VLC + SMB | Jellyfin (Docker) | Plex |
| :--- | :--- | :--- | :--- |
| **Сложность настройки** | Низкая (просто расшарить папку) | Средняя (нужен Docker/контейнер) | Высокая (аккаунт, облако) |
| **Красота (постеры/мета)** | Нет (только файлы) | **Да (полноценная библиотека)** | Да (отличная) |
| **Поддержка плейлистов** | Только через `.m3u` | Автоматически из метаданных | Автоматически |
| **Зависимость от облака** | Нет | **Нет (Полностью локально)** | Да (требует аккаунт/облако) |
| **Вердикт для RPi5** | Идеально для теста | **Лучший выбор для дома** | Не рекомендуется (из-за аккаунта) |

## 3. Предлагаемые топологии развертывания
### Вариант А: Раздельный сервер (Рекомендуется для стабильности)
- **Хост:** Текущая машина с `yt-dll`. Работает как "загрузчик" и SMB/NFS сервер.
- **RPi5:** Выступает в роли медиасервера (Jellyfin). Подключается к папке `videos` по сети.
- **Плюсы:** Легко масштабировать, загрузка не тормозит просмотр.

### Вариант Б: Единый сервер (Все на RPi5)
- **RPi5:** Запускает и `yt-dlp`, и Jellyfin. Хранит файлы на внешнем диске/NVMe.
- **Плюсы:** Минимальное энергопотребление, отсутствие сетевых задержек между загрузчиком и сервером.

## 4. Технические риски и ограничения
1. **Метаданные:** YouTube-рипы не имеют стандартных имен файлов для Jellyfin (нужна обработка или ручная привязка).
2. **Синхронизация "Просмотрено":** Статус просмотренного в `yt-dll` (для удаления файла) и статус просмотра в Jellyfin — это разные данные. Требуется либо ручное подтверждение, либо создание "моста".
3. **Память:** RPi5 требует хорошего питания (27W) и охлаждения при активном использовании медиасервера.
